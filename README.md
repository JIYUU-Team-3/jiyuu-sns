# sns-website

SvelteKit 3 app deployed as a Cloudflare Worker, backed by D1 (via Drizzle ORM) and KV, with Better Auth (email/password + Google) and Paraglide i18n (`en`, `ja`).

## Stack

| Concern         | Tool                                                                    |
| --------------- | ----------------------------------------------------------------------- |
| Framework       | SvelteKit (`next`) + Svelte 5 runes, async components, remote functions |
| Runtime         | Cloudflare Workers (`@sveltejs/adapter-cloudflare`)                     |
| Database        | Cloudflare D1 (`DB` binding, database `sns-db`) + Drizzle ORM           |
| Key-value       | Cloudflare KV (`KV` binding, namespace `sns_kv`)                        |
| Auth            | Better Auth (email/password, Google OAuth)                              |
| i18n            | Paraglide JS, locale resolved by `url` → `cookie` → `baseLocale`        |
| Tests           | Vitest (browser + node projects), Playwright (e2e)                      |
| Git hooks       | Lefthook                                                                |
| Package manager | pnpm (`engine-strict=true`)                                             |

## Getting started

```sh
pnpm install           # also installs the lefthook git hooks
cp .env.example .env   # then fill in the values
pnpm db:migrate:local  # apply migrations to the local (emulated) D1
pnpm dev
```

### Environment variables

Declared in [`src/env.ts`](src/env.ts) and read through `$app/env/private`; `.env.example` lists every key.

| Variable                                                                 | Used by                               |
| ------------------------------------------------------------------------ | ------------------------------------- |
| `ORIGIN`                                                                 | Better Auth base URL                  |
| `BETTER_AUTH_SECRET`                                                     | Better Auth token signing (32+ chars) |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`                               | Google OAuth                          |
| `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_DATABASE_ID`, `CLOUDFLARE_D1_TOKEN` | `drizzle-kit` (remote D1 over HTTP)   |

`wrangler types` bakes the keys from `.env` into `worker-configuration.d.ts`, so a `.env` must exist (placeholder values are fine) before `check` or `build`. That file is generated and git-ignored; every script that typechecks regenerates it.

### Cloudflare bindings

Bindings are declared in [`wrangler.jsonc`](wrangler.jsonc) and read at runtime from `cloudflare:workers` (`import { env } from 'cloudflare:workers'`). Adapter-cloudflare for Kit 3 no longer populates `event.platform.env`. [`src/hooks.server.ts`](src/hooks.server.ts) throws if `DB` is missing, so the app has to run under Vite with the Cloudflare adapter or under wrangler.

## Project structure

```
src/
  env.ts                    # private env var declarations
  hooks.server.ts           # paraglide middleware -> Better Auth session
  hooks.ts                  # reroute: strips the locale prefix from URLs
  lib/server/auth.ts        # createAuth(d1) — per-request Better Auth instance
  lib/server/db/            # Drizzle client (getDb), app schema, generated auth schema
  routes/demo/              # generated demos: better-auth, paraglide, playwright
messages/                   # Paraglide message catalogs (en.json, ja.json)
drizzle/                    # SQL migrations (generated by drizzle-kit)
```

### Import aliases

`#lib` / `#lib/*` map to `src/lib` through the `imports` field in `package.json`, which Vite and Node use. TypeScript doesn't infer extensions or `/index` for `imports` targets, so `tsconfig.json` has a matching `paths` entry. **If you change one, update the other too.**

### Hooks

- `handleParaglide` swaps `event.request` for the de-localized request. Kit 3 made `RequestEvent.request` readonly, so the hook assigns it through a cast to keep paraglide's documented runtime behaviour.
- `handleBetterAuth` creates the auth instance from the D1 binding and puts `auth`, `session` and `user` on `event.locals`.
- `Handle` and `Reroute` types are imported from `@sveltejs/kit/hooks`.

## Database

The schema lives in `src/lib/server/db/schema.ts` (app tables) and `src/lib/server/db/auth.schema.ts` (generated by Better Auth; don't edit it by hand).

| Script                   | What it does                                                                 |
| ------------------------ | ---------------------------------------------------------------------------- |
| `pnpm auth:schema`       | Regenerate `auth.schema.ts` from the Better Auth config                      |
| `pnpm db:generate`       | Generate a new SQL migration in `drizzle/` from the schema                   |
| `pnpm db:migrate`        | Apply migrations to the **remote** D1 via drizzle-kit (needs `CLOUDFLARE_*`) |
| `pnpm db:push`           | Push the schema to remote D1 without a migration (prototyping only)          |
| `pnpm db:studio`         | Open Drizzle Studio against remote D1                                        |
| `pnpm db:migrate:local`  | Apply migrations to the local emulated D1 (`.wrangler/state`)                |
| `pnpm db:migrate:remote` | Apply migrations to remote D1 via wrangler                                   |

`wrangler.jsonc` sets `migrations_dir: "drizzle"`, so drizzle-kit and `wrangler d1 migrations apply` share the same folder. Wrangler ignores `drizzle/meta/`. Commit the whole `drizzle/` directory, including `meta/`, so drizzle-kit can diff future schema changes.

To change the schema: edit `schema.ts`, run `pnpm db:generate`, check the SQL it writes, then run `pnpm db:migrate:local` and commit.

## Scripts

| Script                 | What it does                                                             |
| ---------------------- | ------------------------------------------------------------------------ |
| `pnpm dev`             | Vite dev server                                                          |
| `pnpm build`           | `wrangler types` + production build                                      |
| `pnpm preview`         | Serve the built Worker with wrangler on port 4173                        |
| `pnpm check`           | `wrangler types` + `paraglide` + `svelte-kit sync` + `svelte-check`      |
| `pnpm lint` / `format` | Prettier + ESLint                                                        |
| `pnpm test:unit`       | Vitest (`client` project in Chromium, `server` project in Node)          |
| `pnpm test:e2e`        | Playwright against `pnpm preview:ci` (local D1, no credentials)          |
| `pnpm test`            | Unit tests then e2e                                                      |
| `pnpm gen`             | Regenerate `worker-configuration.d.ts`                                   |
| `pnpm paraglide`       | Compile `src/lib/paraglide` without Vite (flags mirror `vite.config.ts`) |

E2E specs are `*.e2e.ts` files under `src/`, next to the routes they cover. Set `PLAYWRIGHT_BASE_URL` to point Playwright at a deployed URL instead of starting a local server. Tag any e2e test that writes data with `@writes`; the post-deploy run skips those so it never touches production data.

## Git hooks (Lefthook)

- **pre-commit**: Prettier (auto-fixes and re-stages), ESLint on staged files, and `pnpm audit --audit-level moderate` when dependency files change.
- **pre-push**: `pnpm run check` and `vitest --run`.

To skip the hooks for one command, prefix it with `LEFTHOOK=0`.

## CI/CD

Branches: open PRs against `development` or `main`. **`development` is the deploy branch.** Every push to it ships the production Worker.

**CI** ([`.github/workflows/ci.yml`](.github/workflows/ci.yml)) runs on every PR, and `deploy.yml` also calls it as a gate. Jobs run in parallel on Node 24:

- Lint, dependency audit (`pnpm audit --audit-level moderate`), typecheck, unit tests, build
- E2E: builds the app, migrates the local D1, then runs Playwright against `wrangler dev --local`

Every job installs [Aikido Safe Chain](https://github.com/AikidoSec/safe-chain) (pinned and checksum-verified) before `pnpm install --frozen-lockfile`. Jobs that run `wrangler types` first seed `.env` from `.env.example`.

**Deploy** ([`.github/workflows/deploy.yml`](.github/workflows/deploy.yml)) runs on a push to `development` or a manual dispatch:

1. Run the full CI workflow as a gate.
2. Apply D1 migrations (`drizzle-kit migrate`) before the new code goes live.
3. Build, then `wrangler deploy`.
4. Smoke-check the deployment URL, with retries.
5. Run Playwright (Chromium) against the deployment, excluding tests tagged `@writes`.

Deploys are never cancelled once they start.

Required repository secrets (`production` environment): `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_DATABASE_ID`, `CLOUDFLARE_D1_TOKEN`. Runtime secrets (`BETTER_AUTH_SECRET`, `GOOGLE_CLIENT_*`, `ORIGIN`) have to be set on the Worker with `wrangler secret put`.
